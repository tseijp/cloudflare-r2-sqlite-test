# 002 まだ無い行への `cell` / `style` が履歴に残り、後でできた行に undo / redo が書く

状態: 未修正。判断待ち。

## 1. 発生条件

1. client が、その page にまだ無い `_id` (今の最大より大きい番号) を `row` にして `cell` か `style` を送る
2. その後、行が足されて同じ `_id` の行ができる (`row.add`、`import`)
3. 同じ client が `undo` か `redo` を送る

画面の client は見えている行にしか `cell` を送らないので、この順序にならない。`send` を直接呼ぶ利用者 (LLM など) だけが当たる。消した行の `_id` は再利用されないので、消した行では起きない。

## 2. 再現方法

command は repository の root (`projects/_cloudflare-r2-sqlite-test`) で実行する。

```
node_modules/.bin/tsx .bench/run.mjs repro .bench/issues/002.json
```

操作列は `.bench/issues/002.json` にある。行が 1 つも無い page に `row: 1` の `cell` を送り、`row.add` で `_id` 1 の行を作り、`undo`、`redo` を送る。

出力 (2026-11-11 に実行したもの)。

```

0 A page.add p -> ok store []
1 A col.add p -> ok store []
2 A cell p row 1 'ghost' -> ok store []
3 A row.add p -> ok [[1]] store []
4 A undo -> ok store []
5 A redo -> ok store []
5 崩れ 履歴/rows 期待 [[1,null]] 観測 {"length":[1,1],"at":0,"expected":[1,null],"observed":[1,"ghost"]}
6 A sql select * from "p" -> ok [["_id","a"],[1,"ghost"]] 0ms store []

```

| 見る行             | 読み方                                                                  |
| ------------------ | ----------------------------------------------------------------------- |
| `2 A cell … 'ghost'` | 行 1 はまだ無い。SQL は何も変えないが、命令は解決し、履歴に 1 つ積まれる |
| `3 A row.add`      | `_id` 1 の行ができる。本文は null                                       |
| `5 A redo`         | 2 で送った本文が、後からできた行 1 に書かれる                           |
| `6 A sql`          | 行 1 の `a` が `ghost` になっている。期待は null                        |

simulation の生成はこの順序を作らないので、seed では当たらない。

## 3. 期待と観測

| 項目 | 内容                                                              |
| ---- | ----------------------------------------------------------------- |
| 期待 | 無い行への編集は、後からできた行に影響しない                      |
| 観測 | `undo` は後からできた行のその cell を null にし、`redo` は本文を書く |

## 4. 仕組み

compiler は純関数で、行があるかを知らない。編集前の値を置く `fill` と、履歴に積む `set` は、行の有無に関わらず実行される。

## 5. 影響する範囲

`send` を直接呼ぶ利用者が、まだ無い行番号を指定した場合だけである。壊れるのは、後からできたその行の 1 cell の本文か装飾である。

## 6. 直す場合の案

| 案  | 内容                                                                                                     | 変わる挙動                                                    | 行数の見込み                      |
| --- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | --------------------------------- |
| 0   | 直さない                                                                                                 | 無し                                                          | 0                                 |
| 1   | `fill` の問い合わせが 0 行なら命令を reject する。`style` の問い合わせを「位置があれば 1 行」の形に変える | 無い行 / 列への `cell` / `style` が、無視でなく reject になる | executer +2 行、row の plan ±0 行 |

## 7. 判断がほしい点

無い位置への `cell` / `style` を「何もせず解決」のままにするか、reject にするか。
