# fixtures

## 1. 置き場と範囲

計測に使う公開データセットは `.bench/data/` に置き、commit しない。
runner は file 名ではなく実測した性質で class を決めるので、file が入れ替わっても採点表は変わらない。
1 file が 100MB を超えるものは対象外とし、対象外である根拠として置いたままにしてよい。

## 2. class

class は内容と容器と規模の 3 軸の直積で決まり、どの fixture も各軸でちょうど 1 つに入る。

| 軸   | 値               | 判定                                                                  |
| ---- | ---------------- | --------------------------------------------------------------------- |
| 内容 | 細長 numeric     | 列が 10 以下で、数値列が 7 割以上                                     |
| 内容 | 幅広 numeric     | 列が 11 以上で、数値列が 7 割以上                                     |
| 内容 | 短文 categorical | 数値列が 7 割未満で、最長 cell が leaf の上限 (usable size − 35) 以下 |
| 内容 | 長文             | 最長 cell が leaf の上限を超える (overflow page が出る)               |
| 容器 | 単一             | CSV 1 file = 1 page                                                   |
| 容器 | 複数             | xlsx の sheet ごとに 1 page                                           |
| 規模 | 小               | 行数が窓の 100 倍未満                                                 |
| 規模 | 中               | 行数が窓の 100 倍以上 2,000 倍未満                                    |
| 規模 | 大               | 行数が窓の 2,000 倍以上                                               |

手元の公開データセットでは、株価の日次と暗号資産の分足が細長 numeric の大、電力需要の連続観測が幅広 numeric の中、
航空券価格が短文 categorical の大、アプリのレビューと遊園地のレビューと Q&A 分類が長文の中、暗号資産の日足と時間足と電力の週次予報が小、電力の学習用 xlsx が複数容器の中に入る。
runner は少なくとも内容の 4 値それぞれから規模が最大のものを 1 件ずつ選び、複数容器を 1 件足した 5 件を対象 class とする。

## 3. 各 class が試す性質

細長 numeric は leaf 1 枚に 40 行から 65 行が入るため、窓 50 行が leaf 1 枚か 2 枚で済むことと、REAL 8 byte が短い小数の TEXT より大きくなることを露わにする。

幅広 numeric は列幅の合計が方眼紙の 35 マスを超える状況と、float 列が多いときの image の縮小を試す。

短文 categorical は選択肢列を TEXT のまま持つ設計で group by と絞り込みが全走査になることと、
index を作らない方針の所要時間を試す。

長文は 1 cell が leaf に収まらず overflow page に出ること、
quoted 改行、BOM、非 ASCII、header 行の無い CSV を試す。

複数容器は 1 file に複数 page が並ぶときの page ごとの table と、sheet 名から page 名への写像を試す。
小は table 全体が窓より小さいときに窓の入れ替えが起きないことを試す。

## 4. 取り込み契約

- CSV の 1 file は 1 page = 1 table であり、header 行が列名になる
- 空の header は `列N`、重複する名前は `名前 (2)` のように一意化する
- 先頭の BOM は剥がし、quoted 改行は 1 cell に保ち、CR は捨てる
- 列の型は先頭の数千行から推定し、全て整数なら INTEGER、小数が混ざれば REAL、それ以外は TEXT とし、空 cell は NULL にする
- header 行の無い file は 1 行目を値として読み、列名は `列N` にする
- xlsx は sheet ごとに page を作り、sheet 名を page 名にする
- 取り込みは 1 transaction で行い、行 id は取り込み順の rowid そのものにする

取り込み時間は行数に比例しなければならない。
runner は同じ file の先頭 N/10 行だけを取り込んだ image を別に作り、時間の比が 8 以上 12 以下であることを確かめる。
この N/10 image は窓・同期・観測の軸でも「N に依存しないこと」の比較対象になる。

## 5. class ごとの読み替え

長文では f (leaf 1 枚の行数) が 5 から 7 なので、50 行の窓は leaf 8 枚から 10 枚と overflow page を読む。
編集の軸の「50 cell 一括」は ceil(50 ÷ f) + 3 を上限にする式のまま使い、長文では上限が 11 から 13 になる。
小では N/10 image が窓より小さくなるため、窓と観測の軸は「比 1.1 以下」ではなく「N 側の値が窓 1 つ分以下」で満点とする。
