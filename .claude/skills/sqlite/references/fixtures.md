## 2. 製品の上限との関係

database は `LIMIT` = 8,192 page (32 MiB) を超えて伸びない。超える書き込みは失敗し、その transaction は無かったことになる。上の file の大半は全行を入れると上限を超えるので、全行の取込が通ることは性質ではない。通るのは「上限に達するまでの行」と「上限を超えた取込が、それまでの状態を壊さずに拒まれること」である。

## 3. 取込の入口

server の `import` は `{ page, names, rows }` を受ける。`names` は列名の配列 (contract.md 5 節の名前の制約を満たし、大文字小文字を無視して重複しない)、`rows` は文字列か null の配列の配列で、1 回の命令が 1 transaction になる。page が無ければ `names` の列で作り、在れば末尾に足す。行は `names` の位置で読まれ、足りない位置は NULL、余った位置は捨てられる。値は全て TEXT として入る。

CSV の文字列を行に分けるのは client の役目である (`file` event)。BOM を剥がし、`"` で囲まれた中の `,` と改行を値として保ち、`""` を `"` に読み、囲みの外の CR を捨て、空行を捨てる。1 行目が列名になり、空の列名は `列 N`、重複は `名前 (2)`、先頭の `_` は取り除かれる。page 名は file 名から拡張子を除いたものである。

## 4. データの性質として使えるもの

列数、行数、cell の長さの分布、非 ASCII の割合、囲みの中の改行の有無は file ごとに違う。値は実物を読んで測る。この文書は値を持たない。
